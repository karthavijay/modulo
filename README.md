# Modulo on Render

One always-on Render web service that runs the Modulo website, the agent chat, and the course production pipeline, with approval by email.

**Setting it up? Read `SETUP_GUIDE.md`.** This file is for a developer.

## How it fits together

| Path | What it does |
|---|---|
| `render.yaml` | Render Blueprint: Python web service on the Starter plan with a 1 GB disk at `/var/data`. |
| `app.py` | Starlette app: website (`public/`), `/api/chat`, `/api/brief`, `/review/<id>`, `/files/<id>/<name>`, `/dashboard`, `/health`. |
| `agent_chat.py` | `/team` page (dashboard key): one-on-one chat with Iris, Theo or Quinn about a course. Iris/Theo return structured change proposals stored under `proposals/`; `/api/team/apply` saves one (backup kept) and rebuilds md + docx. Course context is prompt-cached. |
| `chat.py` | Website chat via the Anthropic SDK (`claude-opus-5-5`, low effort, JSON schema output, server-side refusal fallback). |
| `jobs.py` | One folder per brief under `$DATA_DIR/jobs/`, a single background worker (one course at a time), status flow, emails. |
| `emailer.py` | Resend API. Without a key, emails are written to `$DATA_DIR/outbox/`. |
| `pipeline/` | The Agent SDK pipeline: Iris, Theo, Quinn (`make_design()`, `make_storyboard()`), then the optional production pack (`make_pack()`: Sam, Vera, Mila, Dev, Lars, Nia, Paige, one Markdown document each, combined into `production_pack.docx`). Instructions in `pipeline/agents/*.md`. Still runnable by hand: `python pipeline/pipeline.py brief.txt`. |

Status flow: `designing -> awaiting_approval -> (revising -> awaiting_approval) -> storyboarding -> done -> (packing -> done, after the owner presses Start the production pack)`, or `failed` with a retry button. On startup the worker re-queues anything left in a working state; the pipeline reuses saved drafts, so a redeploy mid-run loses at most the step in progress.

Approve and change requests are POST forms on the review page (email links only open the page), so mail scanners that prefetch links cannot start a $7 run. Each job has a random token in its links; the dashboard uses `DASHBOARD_KEY`.

## Environment variables

| Name | Required | Notes |
|---|---|---|
| `ANTHROPIC_API_KEY` | yes | Chat and pipeline. |
| `RESEND_API_KEY`, `NOTIFY_EMAIL` | yes | Without a verified domain, Resend only delivers to the account owner's address. |
| `DASHBOARD_KEY` | yes | Generated by the Blueprint. |
| `DATA_DIR` | set | `/var/data` (the disk). |
| `EMAIL_FROM` | no | Defaults to `onboarding@resend.dev`; set after verifying a domain. |
| `MODULO_MODEL`, `MODULO_EFFORT` | no | Pipeline model and effort (default `claude-opus-5-5`, `high`). `MODULO_CHAT_MODEL` for the chat. |
| `MODULO_MAX_ROUNDS` | no | QA fix rounds, default 2. |
| `MAX_BRIEFS_PER_DAY` | no | Default 10. |
| `MODULO_FAKE` | no | `1` = canned forklift answers, no API calls. |
| `PUBLIC_URL` | no | Defaults to Render's `RENDER_EXTERNAL_URL`. Set it when using a custom domain so email links use it. |

## Run locally

```
pip install -r requirements.txt
MODULO_FAKE=1 DASHBOARD_KEY=dev uvicorn app:app --reload
# open http://localhost:8000 and http://localhost:8000/dashboard?key=dev ; emails land in data/outbox/
```

## Notes

- The Agent SDK runs the bundled Claude Code binary as a subprocess. One run at a time should fit the Starter plan (512 MB), but this has not been measured on Render yet; move to Standard if Render reports out-of-memory.
- The disk means zero-downtime deploys are off: a deploy restarts the service for about a minute.
